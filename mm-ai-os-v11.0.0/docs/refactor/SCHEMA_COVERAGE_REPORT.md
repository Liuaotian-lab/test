# Schema Coverage Report — 7.4.0-candidate-official-split

## Summary

`7.4.0` adds the first dedicated candidate-official-split layer for the OS. The goal is to convert high-value natural-language contracts into machine-checked JSON contracts without changing the formal workflow semantics from `7.2.0`.

## Added schema families

| Family | Files | Purpose |
|---|---:|---|
| `problem_understanding` | 6 | Evidence spans, evidence indexes, problem claims, question nodes, final signatures and understanding gate reports. |
| `academic_research` | 7 | Search plans, queries, search results, identified methods, citations and coverage reports. |
| `method_plan` | 4 | Method candidates, plan summaries, review reports and approval records. |
| `contracts` | 6 | Question, variable, objective, constraint, output and validation contracts. |
| `agents` | 3 | Task cards, run reports and allowed-file manifests. |
| `gates` | 2 | Generic gate result and final gate report. |
| `workflow` | 2 | Step result and case state. |
| `artifacts` | 1 | Output artifact metadata. |

## Added validation utilities

- `mmos/core/schema.py`
- `python -m mmos.cli schema-list`
- `python -m mmos.cli schema-validate`

## Added tests

- `tests/unit/schemas/test_schema_registry.py`
- `tests/unit/schemas/test_generated_artifacts_validate.py`
- `tests/unit/cli/test_schema_cli.py`

## Validated generated artifacts

The test suite validates that artifacts generated by the existing workflow still satisfy the new schemas:

- `workspace/problem_understanding/final_problem_signature.json`
- `quality/understanding_gate_report.json`
- `workspace/academic_search/search_results.json`

## Known schema limitations

- Schemas are intentionally permissive on non-core properties to preserve backward compatibility.
- This release does not yet enforce schemas inside every workflow step.
- Formal candidate/official promotion is deferred to `7.4.0`.
- Some historical root-level schemas remain in place for backward compatibility.
