# Context Pack: Schema Gate

## Purpose

The schema gate converts high-value workflow artifacts into machine-checkable JSON contracts. It is introduced in `7.4.0-candidate-official-split` and is intentionally backward-compatible with the `7.2.0` control plane.

## Inputs

- JSON Schema files under `schemas/`
- JSON artifacts generated by workflows or supplied by Agents
- Schema fixtures under `tests/fixtures/schemas/`

## Outputs

- `SchemaValidationResult` dictionaries from `mmos/core/schema.py`
- CLI JSON payloads from `schema-list` and `schema-validate`

## Public APIs

- `mmos.core.schema.list_schemas(root)`
- `mmos.core.schema.schema_path(name, root)`
- `mmos.core.schema.load_schema(name, root)`
- `mmos.core.schema.validate_json_file(path, schema_name, root)`

## CLI

```bash
python -m mmos.cli schema-list
python -m mmos.cli schema-validate --schema problem_understanding/final_problem_signature --file <json-file>
```

## Data Contracts

Core schema families:

- `problem_understanding/*`
- `academic_research/*`
- `method_plan/*`
- `contracts/*`
- `agents/*`
- `gates/*`
- `workflow/*`
- `artifacts/*`

## Allowed Changes

- Add a schema only with matching valid/invalid fixtures.
- Relax schema fields only when preserving legacy compatibility.
- Tighten schema fields only when all generated fixtures and tests are updated.

## Forbidden Changes

- Do not delete legacy root-level schemas without an explicit migration plan.
- Do not make generated `7.1` or `7.2` artifacts invalid unless a migration command is provided.
- Do not use schema validation as a replacement for semantic gates; both are required.

## Tests

```bash
python scripts/run_tests.py --tier schema
python -m pytest tests/unit/schemas tests/unit/cli/test_schema_cli.py
```

## Common Failure Modes

- Missing required field in an Agent-generated JSON artifact.
- Schema reference path not resolvable from `schemas/`.
- Overly strict schema that breaks legacy case artifacts.
- Treating schema pass as semantic correctness.
